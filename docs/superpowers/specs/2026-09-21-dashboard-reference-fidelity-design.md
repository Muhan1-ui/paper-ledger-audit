# 仪表盘参考图高还原设计

## 目标

将本地只读仪表盘的桌面端视觉结构高还原为用户提供的参考图，同时所有指标、表格、图表和状态均来自本地 JSONL 台账、校准报告或调度日志。界面不得使用虚构的日期、环比、赛事、来源观察数或趋势数据。

## 已确认范围

- 优先桌面端 `1440px` 视口，结构、信息密度、留白、色彩和卡片比例以参考图为准。
- 窄屏页面保持可用，但不追求参考图的像素级一致。
- 图表使用可审计的本地派生数据：趋势图基于后来已结算预测的采集日期计算；可靠性图基于报告中的置信度分桶。
- 无足够数据的图表显示明确中文空状态，不以演示曲线补足。
- 仪表盘仍只请求 `/api/summary`，只读且不改写台账。

## 方案比较

### 方案 A：高保真布局 + 扩展真实摘要接口（采用）

Python 摘要层新增趋势序列、可靠性分桶和表格状态字段；静态页面使用 SVG 绘制真实图表。它能复刻参考图的主要信息结构，同时保持数据可追溯、无第三方前端依赖。

### 方案 B：只复刻外观，图表保留演示数据

视觉最快，但会让作品集中的数据叙述失真，不采用。

### 方案 C：只保留当前摘要条和简化布局

实现成本低，但与参考图相差明显，不能满足本次要求，不采用。

## 桌面信息架构

1. 顶部横栏：左侧品牌“体彩数据追踪与校准平台”；右侧只读模式、真实生成时间和刷新图标。
2. 左侧导航：宽度约 `196px`，六个导航入口和底部“平台说明”。导航仅作页面内锚点，不创建虚假功能页。
3. 主区域标题：`数据校准概览`、纸面模拟/本地只读说明以及静态时间范围分段控件。范围控件默认显示“全部”，只有在后端返回对应范围数据时可切换；当前实现先使用全部真实台账数据。
4. 指标行：已结算记录、Brier 评分、对数损失、ECE。移除不可审计的环比数字；统一使用“数值越低越好”或真实状态说明。
5. 图表行：
   - `模型校准趋势`：折线呈现按预测采集日期的 Brier、对数损失、ECE。仅在至少两个有效日期时绘制；图表副标题明确“按已结算预测的采集日期聚合”。
   - `校准可靠性`：散点显示每个有效置信度分桶的平均置信度和实际准确率，虚线为理想校准线。
6. 下方表格：策略表现对比、最近台账活动。策略表保留真实策略名、结算数、三项指标和状态。
7. 右侧栏：运行状态、证据状态、智能体流程。调度过期时显示真实“数据待刷新”，不显示“服务正常”。

## 数据契约

`/api/summary` 保留现有字段，并增加：

- `calibration.trend`: `{ date, brier_average, log_loss_average, expected_calibration_error, settled_records }[]`。
- `calibration.reliability`: `{ confidence, accuracy, records }[]`，只包含有准确率且记录数大于零的置信度分桶。
- 策略行增加真实的 `status`，依据可用性和样本量输出 `available`、`sample_limited` 或 `observational`。

趋势计算使用经过验证、未失效的 `primary` 预测与其关联结算；标准结算记录没有时间字段，因此按预测的 `captured_at` 本地日分组，再调用既有指标函数计算聚合值。可靠性图直接投影 `calibration_report()` 的 `confidence_buckets`，不重新解释或修改概率。

## 错误与空状态

- API 请求失败：保留页面框架，显示“本地汇总不可用”。
- 趋势不足两天：显示“预测采集日期不足，暂不生成趋势图”。
- 没有可用可靠性分桶：显示“当前样本不足，暂不生成可靠性图”。
- 过期调度：显示状态“数据待刷新”与精确年龄，警告由服务端真实日志生成。

## 测试与验证

- 摘要单元测试验证趋势只使用有效结算、按时间排序且不改写台账。
- 摘要单元测试验证可靠性数据仅投影有效分桶。
- 静态页面测试验证主要中文区域、`/api/summary` 和无外部 URL。
- 浏览器以真实账本在 `1440px` 与窄屏截图检查：布局不重叠、图表可见、无演示数据。
- 运行完整 Python 测试套件及只读报告命令。

## 自检

- 没有 TBD、虚构数据或未定义的图表数据来源。
- 后端新增字段与前端消费字段一一对应。
- 改动范围仅为 `dashboard.py`、`dashboard.html` 和仪表盘测试；不编辑冻结 JSONL 记录。
