# 简历与面试材料

## 项目定位

**纸面数据审计与校准追踪系统**（数据源为中国体育彩票足球赛事）。这是一个不涉及购买、资金或投注建议的审计型工程项目：赛前预测、证据事件和赛后结算以内容哈希关联，原始 JSONL 台账不可改写；MySQL 仅作为可重复生成的查询投影，供 FastAPI、仪表盘和复盘 Agent 使用。

当前本地验收数据为 153 条冻结预测、98 条已结算记录。数据规模会随台账增长变化，简历中不建议写死该数字。

## 简历描述

### 后端开发方向

- 设计纸面赛事审计系统，以 JSONL 追加式台账保存冻结预测、证据事件和官方结算，通过内容哈希关联记录，并以结算失效记录保留更正历史。
- 使用 Python、SQLAlchemy、PyMySQL 与 MySQL 8 构建查询投影层，将预测、官方结算、证据观察和采集失败事件同步为只读查询模型；FastAPI 提供健康检查、赛事分页、单场详情与复盘接口。
- 通过 Docker Compose 部署 FastAPI 服务，容器启动时同步投影；以只读卷挂载原始台账、健康检查验证 MySQL 连通性，应用与数据库职责分离。

### 测试开发方向

- 为台账冻结、结算失效、来源证据门禁、MySQL 投影、FastAPI 路由、复盘 Agent 与 Docker 部署配置建立 `unittest` 回归测试；当前全量测试为 494 项。
- 对关键约束采用测试先行：无官方结算不推断赛果、失效结算不进入事实视图、未知赛事返回 404、台账在同步与复盘过程中保持不变。
- 编写服务验收脚本，自动检查健康接口、数据库连接和 Agent 只读模式，支持本机与 Docker 端口验收。

### 全栈方向

- 构建中文本地仪表盘，展示校准指标、可靠性图、策略对比、台账活动、证据状态及 Agent 运行状态；前端通过同一 FastAPI 服务读取 `/api/summary` 和 `/api/reviews`。
- 设计接口失败降级：汇总接口不可用时页面明确报错；复盘接口暂不可用时仅降级复盘状态区，不影响校准与台账展示。
- 使用 FastAPI 自动生成 OpenAPI 文档，前端页面、接口服务和 MySQL 查询投影通过 Docker Compose 统一启动。

### Agent 开发方向

- 实现受约束的只读复盘 Agent：从不可变台账派生“已验证事实、冻结时模型输出、官方结算与数据缺口、校准状态”，保留关联哈希和来源 URL。
- 将 Agent 与外部模型调用解耦：本地复盘无需 API Key；启用 DeepSeek 兼容接口时，仅向模型发送已派生的结构化复盘上下文，模型没有台账写入、外部采集或赛果推断权限。
- 通过规则约束与接口设计防止越权结论：缺少官方结算时明确标记数据缺口，校准样本低于门槛时不进行自动模型调参。

## 高频面试问答

### 为什么同时使用 JSONL 和 MySQL？

JSONL 用于追加式、可审计的事实记录，冻结后不修改；MySQL 解决分页、详情查询和服务化读取。MySQL 数据可由 JSONL 重建，因此数据库故障不会改变原始审计事实。

### 复盘 Agent 和普通报表有什么区别？

报表主要按指标聚合；复盘 Agent 面向单场或全局问题组织上下文，明确区分事实、模型输出和缺口，并返回记录哈希与来源 URL。它可选调用 DeepSeek 做中文叙述，但事实提取、约束校验和权限边界仍由本地代码控制。

### 如何避免模型幻觉或越权结论？

先由本地代码生成结构化、只读的复盘上下文；缺少官方结算时直接生成数据缺口，不让模型补全赛果。系统提示要求引用可用哈希或 URL，且模型没有联网、写台账或调参能力。

### 为什么要把证据观察和采集失败也投影到 MySQL？

它们是数据质量的一部分。把成功观察与失败原因按赛事同步后，接口能回答“为什么没有结论”而不只是返回预测结果，也方便前端展示来源质量和采集状态。

### Docker 部署如何保护原始数据？

Compose 将 `paper_ledger.jsonl` 以只读卷挂载到容器，容器启动先同步 MySQL 读模型，再启动 FastAPI。健康检查只验证服务与数据库连接，不提供任何修改台账的 HTTP 接口。

## 诚实边界与后续计划

以下能力适合作为后续迭代方向，面试中应明确说明当前尚未实现：

- 云服务器、域名、HTTPS、反向代理与访问鉴权尚未部署。
- 没有 CI/CD 流水线、Prometheus 指标或集中式日志平台。
- DeepSeek 调用为可选人工触发的复盘叙述，不是自主采集或自动决策 Agent。
- 当前 MySQL 为本机实例，Docker 容器已实际验证可连接宿主机 MySQL；未宣称为线上高可用部署。
